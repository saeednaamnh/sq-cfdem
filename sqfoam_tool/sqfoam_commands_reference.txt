  TWO RULES THAT MATTER
  ---------------------
  1. ONE coupled `run` at a time (4 cores). new / status / extract / viz are
     safe to use WHILE a run is going. Two runs starve each other.
  2. After a reboot: re-source OpenFOAM + CFDEM in your shell first, then
     `sqfoam doctor`. Sleep is masked, but a reboot still stops a run
     (resume it with `sqfoam run <case>` - it continues from last checkpoint).


------------------------------------------------------------------------------
0) CHECK ENVIRONMENT
------------------------------------------------------------------------------
  sqfoam doctor
      Verifies OpenFOAM, CFDEM, LIGGGHTS, cfdemSolverPisoSQ, libsqCfdem.so,
      restarts, extraction pipeline, postprocess script.


------------------------------------------------------------------------------
1) GENERATE A CASE   (instant, writes files only, safe anytime)
------------------------------------------------------------------------------
  sqfoam new --shape prolate_3 --St 100

  Options:
      --shape   sphere | prolate_2 | prolate_3 | prolate_5    (required)
      --St      Stokes number, any value                      (required)
      --name    custom dir name        (default: shape_StN)
      --steps   DEM shear steps         (default: 5000000)
      --out     parent directory        (default: current dir)


------------------------------------------------------------------------------
2) RUN A CASE
------------------------------------------------------------------------------
  Three ways, depending on whether you want to watch it live:

  (a) BACKGROUND + LIVE LOG VIEW   <-- RECOMMENDED for long runs
      Survivable (terminal close won't kill it); watch whenever you like.
        sqfoam run <case>
        tail -f <case>/log_solve.txt
      (Ctrl-C stops only the tail, NOT the simulation.)

  (b) SCREEN + FOREGROUND   <-- watch live AND survivable
        screen -S v6
        sqfoam run <case> --fg
      Detach (keeps running): press  Ctrl-A  then  D
      Reattach later:  screen -r v6
      (one-time install:  sudo apt-get install -y screen)

  (c) FOREGROUND ONLY   <-- watch live, but fragile
        sqfoam run <case> --fg
      WARNING: Ctrl-C or closing the terminal STOPS the simulation.
      Use only for short tests, not multi-day runs.

  Any interrupted run RESUMES from the last shear checkpoint - just
  `sqfoam run <case>` again. Nothing restarts from zero.


------------------------------------------------------------------------------
3) CHECK A RUN
------------------------------------------------------------------------------
  sqfoam status <case>
      Shows: RUNNING or not, current step, granular temperature, and how
      many orientation frames are written (~100+ needed for a converged fit).

  Live scroll of a background run at any time:
      tail -f <case>/log_solve.txt        (Ctrl-C stops watching only)


------------------------------------------------------------------------------
4) POST-PROCESS  (extract transport coefficients vs. Table I)
------------------------------------------------------------------------------
  sqfoam extract <case>
      Runs the extraction pipeline -> phi, psi, kappa_w, i1, A_xx, A_xz, T
      vs. published Table I. Meaningful once ~100+ orient frames exist.

  Optional:
      --truth /path/to/coefficients_v6.json


------------------------------------------------------------------------------
5) VISUALIZE PARTICLES  (ParaView ellipsoid glyphs, reads only, safe anytime)
------------------------------------------------------------------------------
  sqfoam viz <case> --which shear --res 8

  Options:
      --which   shear | placement       (default: shear)
      --res     ellipsoid mesh resolution, higher=smoother/slower (default 8)

  Then in ParaView:
      File -> Open -> <case>/DEM/results/vtk_shear/collection.pvd -> Apply
      Color by:  orientation_angle   (or speed / particle_type / particle_id)


------------------------------------------------------------------------------
5b) VISUALIZE CFD CONTINUUM FIELDS  (velocity, voidfraction, pressure, Ksl)
------------------------------------------------------------------------------
  sqfoam viz-cfd <case>
      Reconstructs the parallel CFD data and creates a ParaView stub, then
      tells you what to open. Color by voidfraction (shows where particles
      are as a continuum), U (velocity/shear profile), p, or Ksl (drag).

  Faster, skip reconstruct (open processor dirs directly):
      sqfoam viz-cfd <case> --decomposed
      (then in ParaView set Case Type = Decomposed Case)

  Then:
      paraview <case>/CFD/case.foam &
      -> Apply -> Color by: voidfraction

  OVERLAY BOTH (the point of coupled sim): in the SAME ParaView window,
  open the CFD case.foam AND the particle collection.pvd together - you see
  the grains sitting in their fluid field.

  NOTE: unresolved CFD-DEM uses cells bigger than particles, so continuum
  fields look blocky by design (volume-averaged), not a visualization bug.


------------------------------------------------------------------------------
6) FULL GRID  (all 24 St x aspect-ratio cases)
------------------------------------------------------------------------------
  sqfoam grid --full
      Writes all 24 cases into ./physics_grid/. Run each with `sqfoam run`
      as cores allow, or feed physics_grid/manifest.json to a scheduler.
